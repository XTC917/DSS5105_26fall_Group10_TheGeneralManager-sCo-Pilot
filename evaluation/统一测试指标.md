# 统一测试指标

按现在这一版 Co-Pilot 测。每项在 **通过 / 部分通过 / 不通过 / 不适用** 里勾一个。数字以当轮 **Why** 和工具结果为准。

右上角 **Factory** 是全员共用的一个日期。这一轮不要改它，也不要在 Data Management 里导入或删除正式表，不要批准、拒绝或禁用真实账号。

工厂周日休息。查询能看见的记录到查询日的前一天。设定日比库里最新记录早 **2 天或以上** 时，实际查询用「最新记录的次日」，右上角仍显示设定日，Morning 和 Weekly 标题下都有一句 *Data is current through …*。只早 0 天或 1 天时不出现这句。

**通过**：和通过标准一致，没有编造订单、件数、日期、车间或已经发出的邮件。  
**部分通过**：方向对，但漏了一条必须出现的事实，或图/表失败而正文仍可用。  
**不通过**：答错、该拦没拦、不该拦却拦了，或把工具报错贴进正文。  
**不适用**：这一项依赖的界面你这轮没有（例如员工账号没有 Data Management，或邮件服务没开）。

板块分 =（通过 + 0.5 × 部分通过）/（通过 + 部分通过 + 不通过）。不适用不进分母。

测完复制本文件，命名 `统一测试指标_<姓名>.md`。不通过的项填在文末。

## 9. 备注、提醒、观察、邮件

备注、提醒、观察都先出确认。没点 Confirm 不保存。Dismiss 不保存。聊天里的发信确认是模拟，按钮是 *Record simulated send*，不表示客户已经收到。真发信在回答上的 *Open email draft*；邮件服务没开时，发送说明写着需要邮件服务，这项记不适用。

观察的检查日按工厂日计算。Alerts 里：触发日当天在 Active 中显示 Triggered；工厂日晚于触发日时，Active 里不再把它当 Triggered，History 里是 done；工厂日早于触发日时仍是 Watching。这个显示不改数据库里的状态。已取消的留在 History，标成 cancelled。这一轮不要改工厂日去制造触发。
