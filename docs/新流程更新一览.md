# 新流程更新一览

## 1. 问题拦截

### 原流程

```
问句
  → 关键词预路由（routing.py）
       ├─ 靠正则表达式命中「售价 / 营收 / 工人名字」等 → 直接回复「表里没有」，不调 LLM、不调工具
       └─ 没命中 → 全部交给 ReAct
            → 模型自己看系统提示里的工具表，挑工具、算不算、再写回答
```

当时的问题：

- 无法区分没有数据和没有工具
- 拦截过硬导致正常问题无法回答

### 新流程

```
问句
  → 预路由（仍保留；关键词目前为空，一般直接放过）
  → 可提问性两道门（answerability.py）
       第 1 门  这个事实是不是表里的列 / 语义层术语？
       第 2 门  有没有注册工具能查出这一列？
       ├─ 任一门失败 → 停止。回复限制说明。
       │                 证据：assess_stored_data、assess_tool_coverage
       │                 不进 ReAct，不写 few-shot
       └─ 两门都过 → ReAct 自己选工具
 → 通过语义相似度匹配与问题最相似的两个few-shot模板
 → 模型基于工具返回的数据、问题和模板进行回答
```

**第 1 门（数据在不在）**

- 模型看到：问题、语义层数据描述yaml。
- 模型只输出 JSON：`kind`、`stored`、`table`、`column`、`reason`。
- Python 再核对：点名的 `table.column` 是否真在 YAML 的 `data_definition` 里。  
  点了不存在的列 → `stored=false`。  
  `selling_price` 这类 `in_dataset: false` 的术语 → 直接当缺数据。

**第 2 门（工具能不能查）**

- 模型看到：第 1 门的 JSON、全部工具名、以及 **工具对照表**。
- `has_tool=true` 的条件：有工具就是来查这一列的。  
  列名单工具（`find_orders`）按客户/工序过滤也算覆盖，空名单也算覆盖。

**过不了门时的回答**

| 卡住的地方 | 页面上大致会看到 |
|---|---|
| 列不存在 | 「数据里没有这个字段」 |
| 列在，但没有工具 | 「`orders.customer` 在数据里。但没有注册工具能取出它。」（以前 `find_orders` 常误走这条） |

### few-shot模板

模型会严格按照给出的模板进行回答，回答不能保证每次输出的所有文本完全一致，但整体的回答逻辑都会按照模板的方法给出，若后续发现回答不符合预期，需要考虑调整对应的模板回答文字。



测试当前可以正确区分两种不同情况。

*** 当前模型回答中存在偶发bug，当模型不存在相关列时有概率会以西班牙语进行回复，问题不可复现。怀疑是gpt的训练素材中西班牙语较多，导致默认语言选择错误。后续若再观察到可及时记录反馈 ***

## 2. 语义层术语更新

### 这次新加

| 术语 | 经理可能怎么问 | 第 1 门应看成 | 常用工具 |
|---|---|---|---|
| `overdue` | 超期、赶不上交期、哪些单可能 miss due date | 事实；`orders.due_date` 存在。超期/节奏风险是 Python 打的旗 | `get_orders_at_risk` |
| `prioritize` | 今天优先做什么、today's priority | **不是动作**。事实；`orders.due_date`。排序是 Python 分组 | `get_today_priority` |
| `unusual_production` | 产量正不正常、和 30 日中位数比 | 事实；`production_log.pieces_completed`。队列人数看 `orders.current_stage` | `discover_factory_issues` |
| `feasibility` | Can we take / Could we accept … by 某日 | **不是动作**（不是真的下单）。事实；`workshops.capacity_pieces_per_day`。结论是产能估算 | `check_feasibility` |

### 为什么要加

*** 当模型错误认为当前的问题不存在数据时，添加新的语义层term_def ***

*** 当模型错误认为当前的问题没有工具时，在prompt.py的对应工具描述部分进行修改。***
