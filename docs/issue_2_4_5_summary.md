# Issue #2 / #4 / #5 在说什么、哪些可以一起做

给组员看的对照说明。不需要先懂机器学习或后端术语。  
三份 issue 原文：[GitHub #2](https://github.com/XTC917/DSS5105_26fall_Group10_TheGeneralManager-sCo-Pilot/issues/2)、[#4](https://github.com/XTC917/DSS5105_26fall_Group10_TheGeneralManager-sCo-Pilot/issues/4)、[#5](https://github.com/XTC917/DSS5105_26fall_Group10_TheGeneralManager-sCo-Pilot/issues/5)。

文里会用到的几个词：

- **工具**：后端写好的固定功能（查一笔订单、列风险单、估能不能接新单等）。模型负责选哪个工具；加减乘除在 Python 里算，不让模型口算。
- **预路由**：用户一提问，先用关键词挡掉「我们数据里没有的题」（例如卖价、营收），挡住就不调模型、不调工具。
- **会话**：这一轮聊天。现在刷新页面记录会丢；多轮对话靠一个会话编号串起来。

---

## 1. 三份 issue 各自在要什么

**#2（怎么问、怎么看、怎么进门）**

- **千人千面：** 按这位经理刚问过的内容荐下一问，不要永远同一批示例。
- **可视化：** 数字用表、用图，不要只堆在一段话里。
- **新建对话：** 要有按钮；不要只能靠刷新浏览器清空。
- **澄清：** 问题含糊时先给选项反问，再去查数据。
- **拦截：** 挡没有的数据（卖价/营收），不要误伤「订单总体分析」这种能答的题。
- **回答模板：** 工具算出的数一样，写成的句子也要稳，不要每次一套说法。

**#5（界面好不好用、聊天能不能留）**

- **失败提示：** 限流或挂了要等人、能重发，不要甩一长串英文报错。
- **阶段分布：** 各站多少单、多少件，用数量、进度条、标签。
- **风险表格：** 风险订单做成能筛选的表，再加一句建议。
- **历史会话：** 关掉电脑再打开还能看到以前的聊天，并能点进去接着问。

**#4（急不急、早报周报、邮件）**

- **紧急程度：** 今天到期 / 两天内 / 一周内等，程序里算，不要改原始表加一列。
- **排产建议：** 哪种衣服最该先做，让逾期少一点。
- **早报 / 周报：** 工作日弹出早报（已完成 / 还在做）；周一换成周报（上周总结 + 这周待办）。
- **点单提醒：** 图上能点一笔订单设提醒。
- **邮件草稿：** 逾期或可能来不及，生成道歉信 / 完工说明；经理点确认，不要真的从 Outlook 发出去。

## 2. 哪些是同类，可以当成「一件任务」

不是 15 个互不相干的功能。收成下面几件任务。每件写清：**改现有逻辑、加界面，还是新工具**，方便对口的人下手。

### 任务 A — 把查出来的结果画出来

对应：#2 可视化、#5 阶段分布、#5 风险表格、#4 早报/周报里的图。

**改什么：**  
1. **前端图表接口**（不是让模型画一张 PNG）：同一套组件支持表、柱状、饼图、条形进度等。入参是「类型 + 数据」，例如 `{ type: "pie", title: "...", data: [ {label, value}, ... ] }`。  
2. **模型在写回答时带上展示调用**：先调现有查数工具拿到 JSON，再指定 `type`（用户说要饼图就用 pie，没说就用该工具的默认：风险→表，各站件数→柱/条）。前端用接口把图画出来。  
3. **数据必须来自刚才那次工具结果**（或 `traces` 里的行）。模型只选类型、选哪一列当标签/数值，**不许自己编一串数再画**。前端最好校验：图上的数字能在工具 JSON 里对上，对不上就只显示表、并提示。

**不要做什么：** 不要再做一个「去库里查数」的画图工具；画图接口只负责呈现。也不要根据工具名把类型写死到用户无法改（用户明确要饼图时，模型应传 `type: "pie"`）。

**现成数据：** 风险表 ← 「列风险订单」；阶段占比/件数 ← 订单上的当前站、件数。早报的图等任务 F 有数据后，走同一套 `{type, data}`。

**建议先做：** 接口先接通 `table | bar | pie` 三种；默认风险用表、阶段用柱；用户口头要饼图时模型改 `type`。

### 任务 B — 聊天窗口怎么管

对应：#2 新建对话、#5 历史会话、#2 千人千面。

**改什么：** 前端会话状态；第二步再加「把聊天存下来」（后端小接口或浏览器本地存储）。  
**不要做什么：** 不要新的查数工具。推荐问题只读「问过什么主题」。  
**分两步：**  
1. 「新建对话」按钮：换一个会话编号、清空当前气泡、推荐问题回到默认（现在只能靠刷新）。  
2. 历史列表：关掉电脑再打开还能点进去接着问；有存盘之后，千人千面才能跨天。没存盘时，推荐只能根据**这一页已经问过的**来。

### 任务 C — 问清楚再查

对应：#2 澄清、#2 拦截。

**改什么：** 提问入口的现有逻辑，不是新工具。  
- **拦截：** 改现在的关键词挡法（`route_query`）。只挡明确没有的数据（卖价、营收、利润、工人姓名）。「成本分析」「订单总体分析」要放行，去用现有订单/产量类工具。  
- **澄清：** 含糊时不要急着调工具。前端弹出选项（客户/产品/哪一单）；经理点完再查。和现在「匹配到多笔订单时问 order_id」是同一种交互，把它做成固定选项卡片即可。  
**不要做什么：** 不要做「澄清专用查数工具」。

### 任务 D — 把话说稳

对应：#2 回答模板。

**改什么：** 模型的系统提示（怎么组织句子），必要时在「工具已经返回、模型写最后一句之前」塞 1～2 条同类示范。  
**不要做什么：** 不要新工具，也不要把答句模板写进数据说明 YAML。  
**和任务 A 分工：** 表和图给人扫；仍必须用嘴说的（例如接不接得了新单、结论字段必须出现）用示范答法套结构。示范里的数字不准抄，只抄**这一次工具算出来的数**。  
**建议先覆盖：** 查一单状态、风险名单、追溯原因、能不能接新单。

### 任务 E — 「有多急」和排产

对应：#4 紧急程度、排产建议。

**改什么：**  
1. 先在现有「算风险」的 Python 里加紧急程度（今天到期 / 两天内 / 一周内等），**不要改原始订单表加一列**。和已经有的逾期 / 卡住 / 交期太紧用同一套日期规则。  
2. 再新增 **一个** 判断类工具：按产品汇总紧急程度，给出「哪种衣服更该先做」。  
**不要做什么：** 不要三套「紧不紧」的定义；不要为早报再单独算一遍紧急度。

### 任务 F — 早报 / 周报

对应：#4 早报、周报、点单提醒。

**改什么：**  
- 后端 **新做一个** 早报工具（或一个接口）：同一批工厂事实，用参数区分「今天」还是「本周」。卡住的单继续用现在已经约定的 stall，不要另发明一套。  
- 前端：登录弹出 + 可关掉 + 工具栏按钮再打开；布局按日/周两套皮。图用任务 A 的组件。  
- 点单提醒：图上点一笔订单，接到以后的「提醒/值班」动作（本仓库若还没有，先做成界面入口，逻辑跟任务 G 一样要经理确认）。  
**不要做什么：** 不要在早报里重写「能不能找外协」；按钮去调现成的接单可行性工具。

### 任务 G — 邮件草稿

对应：#4 道歉信、完工说明。

**改什么：** 新的「动作」工具：根据订单字段填信模板，返回草稿。界面从早报「生成邮件」点进来。必须先提案、经理点确认，再记一条本地记录。  
**不要做什么：** 不要和早报做成同一个工具；不要接 Outlook、不要真的发出去。

### 任务 H — 出错时人话提示

对应：#5 失败提示。

**改什么：** 只改前端：识别限流/没配密钥/网络失败，显示「请稍后再试 / 重发」，技术细节折起来。  
**不要做什么：** 不改工具、不算数。可随时做，不挡别人。

## 3. 不是同类时，会不会交叉？谁先谁后？

会交叉：很多功能会改到同一块界面或同一套「这单危不危险」。并行硬做，容易出现三套风险定义、三套图表。

建议顺序（前面的给后面垫脚）：

1. **任务 C 把拦截收窄** — 能答的题被挡了，后面演示直接失败。  
2. **任务 H 错误提示** — 改动小，模型没额度时现在就难受。  
3. **任务 A 风险表 + 各站进度** — 不靠新工具也能演示，和 #5 完全对得上。  
4. **任务 D 把接单/查单的说法写稳** — 评测往往看最后那段话。  
5. **任务 C 的澄清选项** — 和「匹配到多笔订单时让经理选」是同一种交互。  
6. **任务 B 先做新建对话**，再做历史存盘和推荐。  
7. **任务 E 只做紧急程度（程序计算）+ 任务 F 早报** — 对应课设里「早上先看一眼」；周报可以第二轮。  
8. **任务 G 邮件草稿 + 点确认**。  
9. **排产建议、真 Outlook、更复杂的 stall、跨天千人千面** — 依赖上面都稳了再做。

交叉关系（做的时候要对一下，避免各做各的）：

- 风险表、阶段图、早报里的图 → 共用任务 A 的表/图，不要做三次。  
- 「还没逾期但快来不及」→ 扩体现有的交期过紧，不要第三套旗标。  
- 「一周内做不完找外协」→ 按钮去调现成的「能不能接这单」，不要在早报里重写产能公式。  
- 新建对话 vs 恢复历史 → 先空会话，再「列表里点开旧的」。  
- 推荐问题 vs 历史记录 → 不存盘就只能根据**这一页已经问过的**来荐；要跨天必须先有任务 B 的存储。  
- 澄清 vs 拦截 → 先别误挡「总体分析」，否则澄清环节都进不去。  
- 回答模板 vs 风险表 → 表做好后，话可以更短；模板留给「必须口述的数字」（例如接单结论）。

## 4. 和分工怎么对上（谁领哪一件）

| 方向 | 更适合领 | 主要是 |
|---|---|---|
| 前端 / 界面 | 任务 A、B、H，以及 F 的弹窗壳 | 加组件、改窗口，不是新查数工具 |
| 提问入口、提示词 | 任务 C、D | 改现有挡法和系统提示，不是新工具 |
| 后端计算、工具 | 任务 E、F 的数据 | E 先扩现有风险计算，再视情况加 1 个排产工具；F 新做一个早报工具 |
| 动作 / 确认 | 任务 G（最后） | 新的草稿工具 + 确认按钮，不发真邮件 |

**一句话：** #2 和 #5 多半是「窗口怎么用、结果怎么看、进门严不严」；#4 是「新的紧急度、早报产品、邮件」。能合并成一件活的，是 **一套可视化、一套紧急度、一个早报工具两套皮（日/周）**。其余是有先后的交叉，不是互不相干的十五件事。
